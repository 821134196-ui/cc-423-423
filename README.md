# 🐾 萌爪美容台 —— 宠物美容预约与护理记录系统

管理宠物档案、服务项目、美容师、预约时段、皮肤毛发备注、用品消耗、照片和取宠确认。
**Python 标准库实现，零第三方依赖**（`http.server` + `sqlite3`），照片存本地目录，提醒走进程内后台任务。

## 一条命令启动

```bash
python3 app.py
```

自动完成：建库 → 空库时预置预约 / 护理 / 异常样例 → 启动进程内通知任务 → 启动 Web 服务。
浏览器打开 <http://localhost:8000>（也可加 `--open` 自动打开）。

常用参数：

| 参数 | 说明 |
|---|---|
| `--port 8000` | 端口（或环境变量 `GROOM_PORT`） |
| `--reseed` | 强制重建演示数据 |
| `--no-seed` | 不预置 |
| `--no-worker` | 不启动通知任务 |
| `GROOM_TICK_SECONDS=1 python3 app.py` | 加快通知扫描节奏（默认 5 秒） |

单独重建演示数据：`python3 seed.py`；运行测试：`python3 -m unittest -v`。

## 六大界面

1. **📅 预约日历** — 周历选日 + 当日预约列表；新建预约保存宠物**品种 / 体型 / 禁忌快照**、
   服务组合与预计时长；「检查时段」实时提示宠物冲突、工位满员、排班不覆盖。
2. **🐶 宠物档案** — 照片 + 标签卡片布局；点开查看皮肤毛发备注、禁忌、主人（演示）资料与历史预约，可直接为该宠物预约。
3. **🧺 工位排程** — 按工位泳道、09:00–19:00 **时间轴**展开，虚线框是美容师排班区间，色块是按容量锁定的预约。
4. **✂️ 护理录入** — 接待确认生成护理单后，护理项目用**大号状态按钮**「完成一项记录一项」（带时间戳/操作人）；
   支持主人临时改项、用品登记、事件登记、照片上传、结单、确认与删除。
5. **📷 异常照片** — 图标 + 文字 + 缩略图组合；异常照片对非授权人员只显示锁形占位，
   即使知道文件名，直接请求文件接口也返回 **403**。
6. **🔑 取宠核验** — 结单自动生成 6 位取宠码，主人报码核验放行；错码 403、重复核验 409。

## 业务规则

- **时段锁定**：`BEGIN IMMEDIATE` 事务 + 重叠区间检测（`b.start < a.end AND a.start < b.end`），
  同一宠物同一时段、同一美容师、工位超容量（capacity）都无法写入。
- **美容师排班按工位容量锁定**：预约必须落在排班覆盖区间内，工位可设容量 >1（如烘干位 2）。
- **护理流程**：`booked → reception_confirmed → servicing → completed → picked_up`。
  接待确认时按预约快照生成护理项目；**未完成项目不能结单**；结单即生成取宠码；护理记录确认后不可删除。
- **主人临时改项**：新增项追加为待完成、去掉的未做项删除、**已完成项保留**，自动重算时长并生成 `change` 事件。
- **六类事件**：宠物抗拒 `resistance` / 皮肤异常 `skin` / 剪伤 `cut` /
  主人临时改项 `change` / 超时未取 `overdue` / 用品过敏 `allergy`；
  剪伤、皮肤、过敏、超时事件同时入通知队列。
- **异常照片**：存本地 `uploads/`，数据库登记 `kind=sensitive`；**只能由授权人员查看**，
  `uploads` 不直接对外开放，取字节流必须过鉴权接口。
- **取宠确认**：码不符 403，护理未完成不能取，已核验不可重复。
- **进程内任务**（`notify.py` 守护线程）：到点提醒发送、失败按 `5s → 15s → 60s` 退避重试、
  达 3 次标记失败；每 ~20 秒扫描「结单超过 30 分钟仍未取」生成超时事件（每单只生成一次）。

## 预置样例（`python3 seed.py` 或首次启动自动执行）

6 只宠物 + 4 位演示联系人；8 个覆盖各状态的预约（待接待 / 已接待 / 护理中 / 待取 / 已取 / 超时 / 未来提醒）；
六类事件各有实例；10 张本地 SVG 照片（含 2 张异常敏感照片）；用品消耗（含燕麦护毛素过敏）；
通知队列含**待重试（前两次失败第三次成功）、已失败、已成功**三种样例，启动后可在右上角 🔔 观察自动重试过程。

## 主要 HTTP API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/meta` | 美容师 / 工位 / 服务 / 用品 / 事件类型 |
| GET/POST | `/api/appointments` | 预约列表（?from&to）/ 新建（冲突返回 409） |
| GET | `/api/availability` | 时段预检（pet/station/date/start/end/staff） |
| POST | `/api/appointments/{id}/confirm-reception` | 接待确认 → 生成护理单 |
| GET | `/api/orders/{id}` | 护理单详情（按查看者身份过滤敏感照片） |
| POST | `/api/orders/{id}/items/{itemId}/status` | 完成 / 撤销一项 |
| POST | `/api/orders/{id}/change-services` | 主人临时改项 |
| POST | `/api/orders/{id}/close` | 结单（有未完成项 409，重复结单 409） |
| POST | `/api/orders/{id}/confirm` / DELETE `/api/orders/{id}` | 确认 / 删除（确认后 403） |
| POST | `/api/orders/{id}/supplies` | 用品消耗（`caused_allergy` 生成过敏事件） |
| POST | `/api/events` | 六类事件登记 |
| GET | `/api/photos` · GET `/api/photo_file?filename=` | 照片列表 / **文件级鉴权**（`X-Staff-Id`） |
| POST | `/api/photos` | base64 上传到本地目录 |
| POST | `/api/appointments/{id}/verify-pickup` | 取宠码核验（错码 403） |
| GET | `/api/timeline?date=` | 工位时间轴 |
| GET/POST | `/api/notifications` · `/api/notifications/{id}/send` | 队列查询 / 手动触发发送 |

> 演示系统用 `X-Staff-Id` 请求头表示当前身份（前端右上角切换，localStorage 记忆）。

## 测试

```bash
python3 -m unittest -v
```

22 个用例全部在独立临时库中运行，覆盖：**并发时段竞争**（同宠物并发 / 工位容量并发 /
容量 2 并行 / 首尾相接不重叠 / 排班覆盖）、**服务变更**（增删改、已完成保留、结单后改项拒绝）、
**照片权限**（服务层 403、HTTP 文件接口 403/200、路径穿越 404）、**重复结单 / 确认后删除 /
重复取宠**、**通知重试**（退避调度、3 次失败、后台线程自动重试成功）、**超时未取事件只生成一次**、
用品过敏与库存扣减、预置数据完整性。

## 文件结构

```
app.py          单命令入口（建库+预置+通知任务+Web）
db.py           SQLite 建表 / 连接（WAL、IMMEDIATE、容量与排班级约束）
services.py     业务服务层（预约锁定、护理流程、事件、照片鉴权、取宠、通知发送）
notify.py       进程内守护线程（到点发送、退避重试、超时扫描）
seed.py         演示数据 + 本地 SVG 照片生成
server.py       HTTP API 与静态资源 / 照片文件级鉴权
static/         index.html · styles.css（柔和绿/海军蓝/桃色）· app.js
uploads/        本地照片目录（敏感照片不直接暴露）
tests/          系统测试
grooming.db     SQLite 数据文件（运行时生成，已 gitignore）
```
